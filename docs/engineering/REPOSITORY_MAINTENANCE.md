# 仓库与资产维护

维护目标：源码、实验指标和解释保持同步；失效产物及时清理；失败案例能被后续项目复用。

## 发布内容

Git 保存当前源码、配置、测试、正式 tokenizer、轻量研究结果、技术报告、异常案例库及来源清单。`report/metrics/` 保存带采样时间的快照与 CSV，区分研究筛查、系统资格、正式训练进展和最终能力。历史 FAIL 不覆盖为 PASS。

语料、token streams、权重、DCP shard、事件日志和大型运行归档通过外部存储与哈希管理。引用不表示 Git 内包含资产；复现需要取得对应资产，不能虚构已发布的下载地址。

## 清理流程

1. 记录候选路径、尺寸、用途和依赖。冻结配方、当前身份、阶段控制器、observer 和历史验收记录引用的文件属于保护集。
2. 检查保护集、进程打开文件和保留实验的证明依赖。日期较早不能作为删除依据。
3. 明确失效的缓存、笔记本备份和旧 checkpoint shard，保存清理清单及必要元数据后删除。仍有引用的历史代码、配置与失败证据保留到引用解除。
4. 删除后复核保护集哈希及实际训练状态；不能为整理仓库重启正常训练。

活跃训练依赖的文件不能移动、格式化或改名。维护工具和文档使用独立路径。历史配置若用于负例测试或审计，应标明范围，不能重新推荐为生产入口。

## Git 更新

提交前检查变更路径、文件大小、凭据、链接和冻结依赖。先完成可审阅本地提交，再推送用户指定仓库；缺少写权限时保留提交与 bundle，明确记录未发布状态，不强推覆盖未知提交。

每次半日复核后更新轻量指标和当前状态；发生故障时追加案例。后台进程负责心跳，半日复核负责解释和决策，无需持续采样 LLM。

`tools/maintain_pretrain_repository.py` 将已完成复核的导出、绘图、当前交接、索引检查和发布串成一次调用；默认只生成并暂存报告，显式 `--publish` 才提交/推送。提供 `YUFORMER_GH_CLI` 和隔离的 `GH_CONFIG_DIR`，图形环境可通过 `YUFORMER_PLOT_PYTHON` 指定。脚本核对账号、之前确认的本地/远端main SHA，拒绝不认识的源码变化、冻结依赖、强制覆盖和同次复核重复发布；额外已审阅路径必须逐项通过 `--include-path` 明确列出。

有域回退的复核不会自动发布，必须先独立调查并写入案例/跟进文档，再用 `--observation-note` 指向包含本次复核时间的记录。这是对已完成分析的工具检查，不是新的用户许可流程，也不会把attention改成PASS或改变训练门禁。该脚本不执行运行检查、不启动/恢复训练、不清理数据，不能替代原半日复核及冻结阶段控制器。执行后以实际远端SHA和外部发布记录核实结果；推送后的网络异常仍需人工核对。

## 经验复用

新增案例记录唯一 ID、阶段、症状、证据、已知/未知根因、最小修复、实际验证、未覆盖情况及可迁移规则。跨项目复用手册、契约、反例和测试方法，再绑定当地模型、数据、硬件与版本重新验证。
