## E0 Tokenizer 实验

### E0-Q1 为什么工业界选择 BBPE？它相比其他算法的本质优势是什么？

**假设**：BBPE 的优势不在压缩率（Unigram 往往更好），而在 ① byte-level 无 OOV（任何 UTF-8 序列可编码）② 跨语言/代码鲁棒 ③ 训练与推理速度 ④ 归一化不脆弱。

| 项 | 内容 |
|---|---|
| 矩阵 | BBPE 三档词表（32k/64k/128k）；~~Unigram 对照~~ **2026-09-25 取消**：HF tokenizers 的 unigram 训练器在生产规模下两次 Rust 级崩溃（16.7M 样本 TryFromInt 溢出 / 6M 样本 Internal 错误）+ 结构性无字节回退——"训练器工业化成熟度"本身成为 BBPE 胜出的第三条实证 |
| 指标 | 压缩率（bytes/token）× 分语言（EN/ZH/code/math）；fertility（tokens/词）；OOV/byte-fallback 率；编码吞吐（MB/s）；训练耗时 |
| **报告产出** | 图 E0-1：四领域 fertility 分组柱状图（BBPE vs Unigram）；表 E0-1：算法对比总表（压缩率/OOV/训练耗时/推理吞吐）；文：BBPE 原理详解（字节基 + 逐对合并贪心，教学章素材） |
| 工业锚点 | GPT-2 引入 byte-level BPE 后 Llama/Qwen/DeepSeek/OLMo 全部跟进；Unigram 止于 T5 时代 |

### E0-Q2 词表大小如何随模型规模缩放？（0.5B 的最优词表）

**假设**：词表 ↑ → 压缩率 ↑（每 token 信息密度 ↑，步数 ↓）但 embedding 参数 ↑；0.5B tied 下 64k 最优，128k 因 embedding 占 54% 参数而劣化。

| 项 | 内容 |
|---|---|
| 矩阵 | 32k / 64k / 128k BBPE（同语料）；代理训练：固定 10B tokens + 固定非 embedding 参数的小模型，比较 loss 曲线 |
| 指标 | 压缩率；代理 loss@10B；embedding 参数占比；等文本量下的训练步数 |
| **报告产出** | 图 E0-2：**三联图**——词表大小 vs（压缩率 / 代理 loss / embedding 参数占比）；表 E0-2：词表消融总表；文："词表必须随模型规模缩放"（Llama2 32k→Llama3 128k 的决策逻辑复现） |
| 工业锚点 | Llama 2（7B, 32k）→ Llama 3（8B, 128k）；Gemma 256k（大模型档）；ZGCM 154,880（7B untied 档） |

### E0-Q3 训练一个大词表的成本与原理（事无巨细环节）

**内容**：BBPE 训练原理逐步拆解（词表初始化 256 字节 → 统计相邻对 → 贪心合并 → O(语料扫描 × 合并轮数)）；实测训练耗时 vs（语料量、词表大小）曲线。

| **报告产出** | 图 E0-3：训练耗时 vs 词表大小（3 档）+ vs 语料量；表 E0-3：单次训练资源账目（语料 50GB / 机器 / 耗时 / 峰值内存） |

## E2 架构消融实验（iso-param ~400M，固定 10B 数据）

E2 的可执行合同是 10 个唯一架构点 × 3 seeds，共 30 臂。全部臂保持相同 token budget、
数据顺序、优化器、调度器和评测集。由于开关项仍会造成少量参数差异，分析器先使用 E1 的
scaling law 将 loss 归一到共同 non-embedding 参数量，再聚合三 seed 均值和标准差；使用
paired-seed 95% CI 确定不可区分集合，并以最低估算 FLOPs 打破统计平局。E1 未 PASS 时不得
给出 E2 排名。

## E4b 三段式训练配方（2026-10-20 v2，对标 WSD/高质量退火路线）

**默认配方 = WSD 三段**（用户裁定）：
- 阶段 A（50B，5%）：`mix_warmup_50b`，按域高质量前缀且提高知识/多语言覆盖；LR 线性 warmup→peak。
- 阶段 B（800B，80%）：`mix_stable_800b`，按域质量前缀组成的主训练分布；LR 保持 stable。
- 阶段 C（150B，15%）：`mix_anneal_150b`，大域 top-10%、精选小域按覆盖要求加深，并提高 math/code/academic；LR 衰减至 min LR。
- 三段均保持 4K context，优化器状态连续。最终 tokenizer（含 EOD）的实际消费边界为 1T；S5 `n_tokens` 只用于选择，不能冒充最终 token 数。
- 长度扩展是独立实验轴：完成 1T/4K 后以 weight-only + optimizer reset 进入 16K 30B→64K 20B，额外 50B 不计入 1T base budget。
- 权威机器配置：`experiments/e4_curriculum/configs/e4_1t_wsd_context.yaml`。

**E4 消融对照**：ZGCM 路线（pretrain 恒定 LR 到底、衰减推到 midtrain）vs WSD 路线——两个工业配方正面对比。
