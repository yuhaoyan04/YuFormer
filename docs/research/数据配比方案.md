# YuFormer 数据配比方案（2026-10-21 v3）

> 输入：当前正式 S6 数据账本。输出：三套实验画像与 1T 三阶段 macro curriculum。
> 原则：配比只决定"从各领域头部取多少"，不改变打分排序本身；所有选取确定性可复现。

## 一、正式供给侧

| 领域 | 治理池 tokens | 100B release candidate tokens | candidate band |
|---|---:|---:|---|
| web | 1,937.020B | 180.346B | exact top-10% docs |
| code | 263.829B | 31.681B | exact top-10% docs |
| chinese | 33.484B | 33.434B | full-pool fallback |
| math | 81.262B | 18.539B | exact top-10% docs |
| academic | 74.391B | 8.148B | exact top-10% docs |
| books | 4.444B | 4.400B | full-pool fallback |
| encyclopedia | 5.389B | 5.339B | full-pool fallback |
| qa | 1.206B | 1.194B | full-pool fallback |
| multilingual | 46.119B | 4.024B | exact top-10% docs |
| **合计** | **2,447.143B** | **287.104B** | exact top-10 subset = 242.738B in five domains |

口径来自 S6 summary 与对应 manifest 的 `effective_top_k`。治理池容量不等于高质量发布容量；top-k 是文档质量分位，不能用 `top_k × pool_tokens` 冒充精确 token 容量。四个 fallback 域的 candidate 账本是全池扫描量，因此 287.104B 不能整体称作严格 top-10%。

## 二、三套配比画像

### M1 池原生画像
200B、池原生领域比例、top-30% collection bound，作为配比从简对照。

### M2 stable 配方
800B 主训练段。配额已经按当前正式池重算：

| 领域 | 目标 tokens | 占 800B | collection top-k 上限 |
|---|---|---|---|
| web | 592B | 74.0% | top-40% |
| code | 96B | 12.0% | top-45% |
| math | 32B | 4.0% | top-50% |
| chinese | 28B | 3.5% | top-90% |
| academic | 28B | 3.5% | top-45% |
| books | 3.2B | 0.4% | top-85% |
| encyclopedia / qa / multilingual | 20.8B | 2.6% | 域别上限见配置 |

### M3 质量极化档
大域保持 top-10%，小域权重按保守 top-10% token 容量下调，母集目标为 200B。旧版“统一 top-10%=490B”估计已作废。

## 三、1T macro curriculum

| 阶段 | 最终 tokenizer 消费目标 | 作用 |
|---|---:|---|
| warmup | 50B | 按域高质量前缀、多领域稳定起步；LR 升至 peak |
| stable | 800B | 主训练分布；按域质量前缀取样 |
| anneal | 150B | 大域 top-10%、精选小域加深重放，提升代码/数学/学术占比；LR 衰减 |

三阶段合计 1T，允许 warmup/anneal 与 stable 有意重叠，要求至少 800B reference-token 唯一覆盖并发布跨阶段 doc_id 重复账本。最终训练 token 以 gated 64K tokenizer 物化结果为准。

## 四、E3 实验臂集合（8 臂，围绕 M2，架构与实际 token 量固定）

| 臂 | 配比 | 检验假设 |
|---|---|---|
| `e3_m1_native` | M1 池原生 | 均衡调配是否优于池原生 |
| `e3_m2_base` | M2 均衡（基线） | — |
| `e3_code_2x` | M2 但 code 份额 ×2 | 代码加倍是否降低 code val loss 且不伤整体 |
| `e3_math_2x` | M2 但 math 份额 ×2 | 数学加倍的价值 |
| `e3_chinese_2x` | M2 但 chinese 份额 ×2 | 中文加倍的代价/收益 |
| `e3_academic_2x` | M2 但 academic 份额 ×2 | 学术语料加倍的代价/收益 |
| `e3_encyclopedia_2x` | M2 但 encyclopedia 份额 ×2 | 百科小域加倍的代价/收益 |
| `e3_m3_quality` | M3 quality-prefix 极化 | 质量极化与广覆盖的同算力比较 |

每臂使用 E2 选定架构、同一 seed、同一验证集和同一 optimizer-step 对齐预算：
9,999,745,024 个实际训练 tokens（名义 10B，取整短差 254,976）。指标包括聚合及九域
held-out loss、实际吞吐和数据响应斜率。E3 是单 seed 配比筛选；0.002 aggregate-loss
实用等价带内优先选择最接近 M2 的配方，不把微小差异解释为统计显著收益。候选还必须满足
九个 held-out 域相对 M2 的 loss 回归均不超过 2%；严重牺牲小域来换取聚合指标的臂只用于
响应分析，不能直接冻结为 1T 配方。分析阈值使用独立 policy 文件，因此不会改变八条数据流的身份。

## 五、验证集留出（S6 职责）

打分池内按领域**确定性**切出 held-out 验证集：每领域 50–100M tokens（合计 <1B，占池 <0.02%，不影响训练量），永不进任何训练臂；同时作为评测去污染的边界集合之一。各领域 val loss 是 E1 的核心指标，留出必须在任何物化之前完成并写进 manifest。
